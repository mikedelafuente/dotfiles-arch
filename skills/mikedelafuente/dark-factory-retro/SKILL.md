name: dark-factory-retro
description: Analyze a specified dark-factory run and propose evidence-backed improvements, with private drafts and separately authorized source-scoped publication.
---

Find `dark-factory` by its catalog path or `<skills-root>/dark-factory/SKILL.md`
in the flat installed skill root. Load that leaf folder's references; verified
source-checkout fallbacks are
[contracts](../dark-factory/references/contracts.md) and
[privacy/publication](../dark-factory/references/retro.md). Resolve installed `retro`
and `writing-for-agents` through the adapter contract. Compose their analysis
categories; this wrapper owns publication and prevents retro's recommendations
from becoming implementation actions.

Inputs: specified run/iteration, permitted evidence, pinned skill/source provenance,
project guidance/ADRs and separate accepted retro/publication policy. Resource
caps are optional in observe-only calibration; content/destination and finite
publication-count authorization remain separate. Optional
run-end invocation requires charter authorization; direct invocation remains bounded.

1. Load the compact manifest and selectively inspect scoped private evidence.
   Read [usage reporting](../dark-factory/references/metrics.md); include this retro
   as its own measured item and compare the project's model/effort/phase aggregates.
   Examine failures, repairs/no progress, successes, interventions, time/cost,
   capability mismatch and available measurements. Reuse existing checks; classify
   mechanical guardrail gaps separately from judgement guidance.
2. Attribute each supported finding to project guidance/ADRs, reusable skill behavior
   or an evidence gap. Project-specific mistakes stay in private project records
   or their separately authorized tracker. Speculation stays a question/draft.
3. Produce prioritized proposals with skill/version, evidence IDs, confidence,
   expected/observed behavior, minimal synthetic reproduction, acceptance criteria
   and rationale. Record reproductions as future validation; do not execute them.
   Generalize from scratch: redacted proprietary context may remain confidential.
4. Resolve the actual recorded skill source/revision and current repository identity,
   including verified moves/renames; never infer it from a checkout basename or
   edit installed copies. The initial source is
   [mikedelafuente/dotfiles-arch](https://github.com/mikedelafuente/dotfiles-arch).
   Missing provenance/access/credentials or offline/denied publication yields a draft.
5. Validate content/destination authorization and privacy clearance, reserve the
   separate publication policy and any configured budget, and source-scope a stable generalized fingerprint.
   Search existing issues and prior proposal/action outcomes. Link an existing
   finding; update it only when separately authorized. Persist intended action
   identity before publishing and confirmed/uncertain outcome afterwards.
   Uncertain creation requires reconciliation before retry; no duplicate issues.

Completion: concise human findings, private detailed evidence, generalized proposals
and bounded draft/linked/published/parked outcomes. No executor dispatch, recursive
retro, source/installed-skill editing, implementation, installation or promotion.
Active versions stay pinned. Future changes require separately authorized versioned
implementation, replay/regression validation and deliberate adoption in later runs.
