## 🪟 tmux Essentials

**Prefix Key:** `Ctrl+B` (press first, then command key)

### Quick Start
- `tmux attach` — Attach to a session (`tmux ls` to list)
- `dev --tmux [dir]` — New tmux session: `code` window (Neovim + agent pane; focus starts on the agent), `console` window (shell in the project dir), optional `lazygit` for git repos
- Arch / Ubuntu 26.04 editor setup: `bash scripts/setup-neovim.sh` then `bash scripts/setup-dev.sh` (Node/NVM first). Requires stable Neovim 0.12+, tree-sitter CLI 0.26.1+, tmux 3.2+. Sources/configs are retained; resolve conflicts explicitly. See `packages` for sources and runtime limits.
- `dev --tmux [dir] --agent claude|codex` — Same, but pick the agent explicitly
- `Ctrl+B` `d` — Detach (session keeps running)

### Most Used Commands
| Keys | Action |
|------|--------|
| `Ctrl+B` `%` | Split pane right |
| `Ctrl+B` `"` | Split pane down |
| `Ctrl+B` arrow keys | Focus pane left / down / up / right |
| `Ctrl+B` `c` | New window |
| `Ctrl+B` `n/p` | Next / previous window |
| `Ctrl+B` `?` | Show all keybindings |

> **Tip:** Run agents like `claude` inside panes; `Ctrl+B` `[` scrolls back through pane output
> **Tip:** `dev --tmux --agent claude` bridges Neovim and Claude automatically (via `claudecode.nvim`) — `<leader>as` in Neovim sends a selection or file to the Claude pane and jumps focus there. See `config/nvim/README.md` for keybindings.
> **Tip:** Any file Claude or Codex edits in a `dev --tmux` session automatically opens (or reloads, if already open) in the Neovim pane — no manual `:e` needed.

### Product ideas with your agent

`agent-council` engages only relevant PM, TPM, Architect, Analyst, and Engineer roles.
BA owns product/domain web research; TPM owns interoperability and integration research.
Both check existing research first; project findings go in `docs/market-research/`
by default unless explicitly told not to store research.
Use `/grill-me` or `/grill-with-docs` for an interview without the council;
use `/advise-me` or `/advise-with-docs` for automatic council recommendations.
The `with-docs` variants record accepted terms/decisions in glossary/ADRs.
You answer the real questions. Accepted Q/A feeds `/to-spec` and `/to-tickets`;
`/bro` simplifies the explanation. Agent skills, not shell commands; distributed
by `dfa-sync-skills`. Simple questions stay compact; disputed choices get bounded
debate and explicit dissent. See `skills/mikedelafuente/agent-council/references/examples.md`.

Personal integrations: `/ask-mike`, `/council-handoff spec|tickets`,
`/build-with-ponytail`, and `/review-changes`. Matt/Ponytail source folders stay
unchanged; their direct invocations retain upstream workflows. See `skills/README.md`.

Skill source overwrite policy defaults to false. Use
`dfa-sync-sources add /path/to/source --overwritable true` to let higher-priority
sources, including dotfiles-arch, replace its duplicate skills silently. Protected
collisions stop sync; `dfa-sync-sources list` shows the setting.

`dfa-sync-sources` manager option **5** toggles skill overwrites for an existing
source. It displays the current setting; changes apply on the next skill sync.

### Cloud agent baseline

In a second dotfiles checkout, run
`bash /path/to/dotfiles-arch/scripts/install-cloud-agent-config.sh --home "$HOME"`.
Installs shared skills and the flattened always-on rule baseline only; no Arch
packages or desktop settings. Keep that checkout available and preserve the
project's existing setup/`AGENTS.md`. Verify discovery in a fresh cloud task.

Desktop IDEs: standalone `scripts/setup-zed.sh` / `scripts/setup-orca.sh` support Arch and Ubuntu 26.04. Ubuntu favors genuine in-app self-updates (keep enabled); existing Orca DEBs refresh via `dfa-update-system`. Zed needs Vulkan and 1.18+; GPU/desktop runtime remains unverified. Source/config/MIME conflicts preserve user choices.

GPU setup on Arch / Ubuntu 26.04: `bash scripts/setup-nvidia.sh --install` explicitly
opts in; `--yes` alone does not. Existing driver stacks are retained. Reboot/MOK
activation can remain pending. `bash scripts/setup-ollama.sh` requires working
CUDA or hardware Vulkan 1.2+, never a software CPU ICD. Ubuntu's verified archive
uses `systemctl --user status ollama` / `journalctl --user -u ollama`; native
packages use the system service. `dfa-update-system` owns refreshes and preserves
disabled services. Models and GPU inference remain unverified; details: `packages`.

Work apps on Arch / Ubuntu 26.04: `bash scripts/setup-{chrome,slack,zoom}.sh`.
Arch retains scanned AUR ownership. Ubuntu Chrome/Slack use scoped vendor APT;
Zoom uses a signed official DEB refreshed by `dfa-update-system` (daily/weekly).
Conflicting sources/launchers are preserved and reported; user settings and
Chrome's work-profile browser identity stay unchanged. Full Ubuntu profile/GNOME
setup is still guarded; install/update/Wayland runtime remains unverified.
See `packages` for source keys, source conflicts, and update owners.

Desktop utilities on Arch / Ubuntu 26.04: `setup-tableplus.sh`, `setup-postman.sh`,
`setup-spotify.sh`, `setup-obsidian.sh`, `setup-moonlander.sh` under `scripts/`.
Ubuntu TablePlus/Spotify use vendor APT; Postman uses official Snap or a retained
user archive updater. Obsidian's in-app updates do not refresh Electron:
`dfa-update-system` refreshes its verified installer DEB and Keymapp's pinned archive.
A changed Keymapp archive requires pin review. Snap automatic updates/holds stay
with Snap. First ZSA setup: log out/in, replug keyboard; custom udev conflicts are
preserved. App/keyboard runtime remains unverified; sources and owners: `packages`.

Appearance: `bash scripts/setup-fonts.sh` provides the shared Adwaita/Noto/Liberation
and Nerd Fonts on Arch/Ubuntu 26.04. Downloaded appearance pins refresh through
setup/full sync; daily native updates do not refresh those pins. See `packages`.
